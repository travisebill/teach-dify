Lesson 0001
本地起 Dify · 第一個 Hello World Chatbot

🎯 這課的 win
60-90 分鐘後，你會有一個跑在 http://localhost 的「自己」的 Dify instance + 一個能聊的 Hello Dify Chatbot。可 demo、可繼續推到 Lesson 2。

為什麼不直接做客服 Chatflow？

官方 Customer Service Bot 教程對應你的 mission，但它要 Chatflow + 4 個 node + embedding model，一次太多觀念。Lesson 1 先把「我的 Dify instance 起得來 + UI 會動」這條 baseline 確認，Lesson 2 專注 RAG / Question Classifier 等觀念。

先決條件

  • 硬體：CPU ≥ 2 cores · RAM ≥ 4 GiB（macOS Docker Desktop 配 VM 至少 2 vCPU / 8 GiB）
  • Docker：Engine 19.03+ · Compose 2.24.0+（docker compose version 驗證）
  • CLI 工具：git · curl · jq（macOS: brew install jq）
  • 網路：連 github.com 與 docker pull registry
  • LLM API key：至少一個（OpenAI / Anthropic / Gemini / Ollama 至少一個）。沒的話可以 Step 1-2 先做，Step 3 再補
注意

首次 docker compose up -d 會 pull 較多 image，視網速 3-10 分鐘。預先跑一次不要在趕時間時做。

Step 1 — Clone & 啟動 Dify

整段步驟 verbatim from Dify 官方 Docker Compose 文件。

1.1 clone 最新版 source

git clone --branch "$(curl -s https://api.github.com/repos/langgenius/dify/releases/latest | jq -r .tag_name)" https://github.com/langgenius/dify.git

這段會用 jq 從 GitHub API 抓最新 stable release tag，checkout 該 branch。如果本機沒有 jq，要先裝。

1.2 進 docker 目錄 + 設定 env

cd dify/docker
cp .env.example .env

所有 Dify config（DB / Redis / port / vector store / provider 開關）都集中在 .env。第一次跑可以先不動，預設值就能起。

1.3 起動容器

docker compose up -d
他會起什麼

6 core services: api · api_websocket · worker · worker_beat · web · plugin_daemon
6 dependent components: weaviate（向量 DB）· db_postgres · redis · nginx · ssrf_proxy · sandbox
1 one-shot: init_permissions（跑完會 Exited，是正常的）

1.4 驗證容器都健康

docker compose ps

應該看到所有容器 Up 或 healthy（init_permissions 是 Exited 0）。如果有容器一直 Restarting，看 Step 1.5。

🛠 卡住時常見原因

  • port 衝突（80 / 443 / 5432 / 6379 / 8080 等）→ 停掉佔 port 的東西，或改 .env 內 port 設定（NGINX_PORT、POSTGRES_PORT 等）
  • RAM 不夠 → docker stats 看，Dify 全跑約要 3 GiB
  • Docker Compose 舊版 → docker compose version 要 ≥ 2.24.0
  • 舊版 container 衝突 → docker compose down 然後重 up -d

其他細節見 Common Issues 或貼 log 問我。

Step 2 — 初始化 admin 帳號

第一次訪問 http://localhost/install 設定 admin：

  • Email: admin@yourcompany.com（這是登入帳號）
  • 密碼: 自己設（建議馬上存到密碼管理器）
  • Workspace name: 填你的公司或專案名（之後還能改）

完成後會自動導到 http://localhost。用剛設的 admin 帳號登入。第一次登入通常會引導你進 Studio——這是建 app 的地方（但 Lesson 1 我們手動走一遍）。

Step 3 — 加 Model Provider

Dify 需要 LLM 才能回應。預設沒附任何 provider，要自己加。

  1. 左側 menu 點 Settings → Model Provider
  2. 選你要的 provider（推薦 OpenAI，最通用）
  3. 填 API key，按下儲存
  4. 回到 Model Provider 頁，點右上 Default Models，把 System Reasoning Model 設成你選的模型（gpt-4o-mini 便宜又快，gpt-4o 比較準但貴）
還沒有 OpenAI key？

先加 OpenAI provider 並隨便填個 API key 是可以儲存的——只是實際發訊息會 fail。或者改用 Anthropic / Google Gemini / Ollama（本地 LLM，不需 API key 但要本機跑得起 model）。

不管怎樣，Step 3 完成前不要進 Step 4——沒 model Chatbot 跑不起來。

Step 4 — 建第一個 Chatbot

  1. 頂部 menu 點 Studio
  2. 右上 Create from Blank → 選 Chatbot（不是 Chatflow。Lesson 1 我們從最簡單的開始）
  3. 命名 Hello Dify，icon 可選 → 按下 Create
  4. 你會進到 prompt engineering 介面

把下面的 system prompt 貼進「Instructions」欄位：

你是 Dify 的教學助手。你的任務是用簡短中文回答 Dify 初學者的問題。

  • 回答不超過 3 行
  • 不確定就說「我不確定，建議查官方文件」
  • 不回答跟 Dify / LLM 無關的問題

右側「調試與預覽」面板可以直接打字試 LLM 怎麼回。例如輸入：

  • 你好 → 應該回友善的招呼
  • Dify 是什麼？ → 應該回 Dify 簡介
  • 今天台北天氣？ → 應該禮貌拒絕（不在範圍）

Step 5 — Publish + 在 WebApp 測

  1. Studio 右上按 Publish → Publish Update
  2. 發佈後，左邊「Monitoring」 menu 點進去 → 看到 Hello Dify 列在「Apps in use」旁邊有個 Visit WebApp 連結（或在 Studio 卡片右上角）
  3. 點進去，打字「你好」或「Hello」，看 LLM 回應
✅ Win 達成

如果你看到 LLM 用友善中文回應你「你好！」之類的——Lesson 1 的 win 達成了。截圖存到 ~/.openclaw/workspace/teach-dify/screenshots/（沒這個資料夾自己 mkdir）。

Step 6 — 自我驗證清單

全部勾完才進 Lesson 2：

  • docker compose ps 所有容器都 Up 或 healthy（除了 init_permissions 是 Exited 0）
  • http://localhost/install 成功設了 admin
  • http://localhost 能登入 admin
  • Model Provider 已加 + System Reasoning Model 已設
  • Hello Dify Chatbot 已建立 + 進 prompt engineering
  • Publish 成功 + WebApp 上能跟 LLM 對話（至少一個來回）
  • （建議）截圖存到 ~/.openclaw/workspace/teach-dify/screenshots/0001-hello.png

Quiz — 取回長期記憶

做 retrieval practice，把今天的關鍵字釘在腦海。答完先不要看解釋，自己想一下再看：

Q1. Dify self-host Docker Compose 預設起多少個 container？分幾類？

6 core = api / api_websocket / worker / worker_beat / web / plugin_daemon。6 deps = weaviate / postgres / redis / nginx / ssrf_proxy / sandbox。另外有個 one-shot init_permissions（Exited 是正常的）。

Q2. 第一次跑 Dify 設 admin 帳號的 URL 是？

是 /install，不是 /setup 或 /admin。設完後主入口是 /（登入用）。

Q3. Lesson 2 我們要從 Chatbot 升級到 Chatflow，原因是？

Chatbot 也可以接 KB（AI 自己決定用不用），但客服需要明確分流（問題相關 → 走 KB；不相關 → 直接拒絕）。這要 Question Classifier 或 If-Else node——只有 Chatflow / Workflow 才有。
